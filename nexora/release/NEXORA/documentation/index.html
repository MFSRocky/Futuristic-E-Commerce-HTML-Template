NEXORA Documentation

Thank you for choosing NEXORA, a premium, futuristic multi-page e-commerce HTML template for audio, wearables, gaming and lifestyle-tech stores. It's built with semantic HTML5, modern CSS3 and dependency-free vanilla JavaScript.

13 HTML pagesHome, shop, product, categories, wishlist, cart, checkout, about, contact, FAQ, blog, article, 404
Zero dependenciesNo frameworks, no jQuery, no build step required
Working storefront UICart, wishlist, coupons, filters, quick view, validation, all persisted in localStorage
Accessible & responsiveTested from 320 px to 1920 px; keyboard and screen-reader friendly

Introduction

NEXORA is a static front-end template. Every page is a plain .html file that you can open, edit and upload to any web host. All interactive store features run in the browser:

  • Product search, category, price and rating filters, sorting, grid/list view and "load more"
  • Quick-view modal, product gallery with zoom, colour and size variations
  • Cart drawer and cart page: add, change quantity, remove, live totals, free-shipping progress
  • Wishlist, coupon codes, a checkout interface with full validation, and order-success state
  • Mega menu, search overlay, mobile navigation, toasts, skeleton loaders and empty states

Important: checkout and payment are demonstrations. NEXORA has no server, database or payment gateway. No order is created, no card is charged and no data leaves the browser. To sell real products you must connect the template to an e-commerce backend or payment provider. See Connecting a backend.

Installation

1. Preview locally

You can double-click template/index.html to open it. For the most accurate results (some browsers restrict localStorage on file:// URLs), run a tiny local server from the template folder:

# Python 3
python3 -m http.server 8080
# or Node.js
npx serve .

Then visit http://localhost:8080. Editors such as VS Code ("Live Server" extension) work too.

2. Upload to your host

Upload the contents of template/ (not the folder itself) to your web root (public_html, www, etc.) via FTP, your hosting file manager, or a static host such as Netlify, Vercel, Cloudflare Pages or GitHub Pages. No build step, database or server language is required.

3. Configure the 404 page

Most static hosts automatically use 404.html. On Apache, add this to .htaccess:

ErrorDocument 404 /404.html

Cache-busting

CSS and JS links end in ?v=1.0.0. When you deploy changes, find and replace that string in all HTML files (for example with ?v=1.0.1) so visitors get the new files.

  --c-cyan:   #FFB547;   /* new secondary accent */

A few decorative glows use the accent as an rgba() value (search for 168, 85, 247 and 0, 229, 255). Replace those for a complete re-skin.

Logo, favicon & brand

  • Logo: the header and footer logo is inline SVG plus text inside <a class="logo">. Replace it with your own <img src="assets/images/brand/logo.svg" alt="Your brand"> or edit the text. A standalone logo.svg is included.
  • Favicon: replace assets/images/brand/favicon.svg. Add a PNG fallback if you need one.
  • Store name & meta: each page has its own <title>, <meta name="description"> and Open Graph tags in the <head>.
  • Theme colour: <meta name="theme-color" content="#090B12"> tints mobile browser chrome.

Header, navigation & footer

Tip: edit the region in one page, then use your editor's multi-file find & replace (VS Code: Ctrl/⌘ + Shift + H) to apply it to all 13 files. If you use a server language or static-site generator, move these regions into includes or partials.

Active menu item

The current page's link carries aria-current="page", which also draws the active indicator. Update it when you copy a page.

Mega menu

The "Shop" item contains a mega menu (.mega) with category links, quick links and a featured panel. It opens on hover (pointer devices), on click, and with the keyboard (Enter/Space, Esc to close). The "Pages" item is a standard dropdown.

Announcement bar

Messages rotate every 4.5 s (static when reduced motion is preferred). The close button hides the bar permanently for that visitor (localStorage: nexora.announce.closed).

Categories, colours & coupons

Edit categories (id, name, icon, tagline, description, image), colors (name, hex, filter) and coupons in the same file. If you add a category, also add its links to the mega menu, footer and shop filter checkboxes.

Product lists & sections

Any element with data-products is filled automatically with product cards:

<div class="product-grid" data-products="trending" data-limit="4"></div>
<div class="product-grid" data-products="new" data-category="audio" data-limit="3"></div>

Values: trending, new, bestsellers, sale. Other handy attributes:

  • data-reveal (or ="fade", ="scale") animates an element in on scroll. Add style="--rd:120" for a 120 ms delay.
  • data-countdown="2026-12-31T23:59:59" with children [data-cd=d|h|m|s] creates a countdown. Without a date it rolls to the end of the current week.
  • data-action="add|wish|quick" data-id="slug" on any button adds to cart, toggles wishlist or opens quick view.
  • data-action="open-cart" and data-action="open-search" open the drawer or the search overlay. data-count="cart|wishlist" shows live counters.

Checkout (demo only)

checkout.html shows a complete, validated checkout interface: contact, address, delivery options, a card form with formatting (number groups, MM/YY expiry, CVC), terms consent and a live order summary. On a valid submit it shows a success modal and clears the cart.

No payment is processed and no data is sent anywhere. A notice on the page tells shoppers that it is a demo. Remove that notice only once you have connected a real payment provider. Never collect real card numbers in your own HTML forms; use your provider's hosted fields or checkout (for example Stripe Elements or PayPal Checkout) to stay PCI-compliant.

Demo card for testing the flow: 4242 4242 4242 4242, any future expiry, any 3-digit CVC.

Forms & validation

Add data-validate to inputs inside a .field wrapper with a .field__error message. Rules can be combined, separated by spaces:

<div class="field">
  <label for="email">Email <span class="req" aria-hidden="true">*</span></label>
  <input class="input" id="email" type="email" data-validate="required email" aria-describedby="email-err" required>
  <p class="field__error" id="email-err">Enter a valid email address.</p>
</div>

Available rules: required, email, phone, zip, card (Luhn check), expiry (future MM/YY), cvc, min10 (10+ characters), checked (checkbox). Fields validate on blur and on submit. Errors are announced with aria-invalid and aria-describedby, and focus moves to the first invalid field. Add your own rules to NX.validators in components.js.

Newsletter forms use <form data-newsletter> followed by a sibling <p class="form-message">.

JavaScript architecture

Vanilla ES5-compatible JavaScript in five files, loaded with defer in this order: data.js → core.js → components.js → pages.js → main.js. Everything is namespaced under window.NX, with no globals beyond NX and NX_DATA.

Create a new page

  1. Duplicate a simple page such as about.html and replace the content between the PAGE CONTENT comments.
  2. Set a unique <title> and description, and set <body data-page="…">. Use a name without a controller (for example about) for static pages.
  3. Link the page from the navigation, the Pages menu and the footer as needed.

Animations & reduced motion

  • Hero entrance choreography ([data-hero] with --d delays), scroll reveals via IntersectionObserver, page fade transitions between internal links, drawer/modal/menu transitions, button loading and success micro-interactions, and a marquee.
  • Only transform and opacity are animated, for smooth 60 fps performance.
  • prefers-reduced-motion: when the visitor's OS requests reduced motion, transitions and animations are reduced to near-instant, reveals show immediately, the marquee and announcement rotation stop, and smooth scrolling is disabled.
  • Without JavaScript all content stays visible, because reveal styles only apply when html.js is present.

Accessibility

  • Semantic landmarks (header, nav, main, footer), one h1 per page, logical heading order, and a skip link.
  • Full keyboard support: menus, mega menu, tabs (arrow keys), accordions, gallery, carousel, modals and drawers with focus trap, Esc to close and focus return. Press / or Ctrl/⌘ + K to open search.
  • ARIA where it adds meaning: aria-expanded, aria-controls, aria-pressed, aria-selected, aria-current, live regions for toasts, counts and results.
  • Every form field has a label; errors are linked with aria-describedby.
  • Visible :focus-visible rings and touch targets of 40–44 px or more on mobile.
  • Tested with axe-core (WCAG 2.1 A/AA rules plus best practices) at 390, 768 and 1440 px: 0 violations on all 13 pages, including colour contrast.

Keep alternative text meaningful when you replace images, and use alt="" for purely decorative images.

Browser support & performance

Latest two versions of Chrome, Edge, Firefox and Safari (macOS and iOS), plus Samsung Internet. The template relies on CSS custom properties, Grid, clamp(), backdrop-filter (with a solid fallback), IntersectionObserver and the inert attribute.

  • No external requests: fonts, icons and scripts are all local.
  • Total template weight with demo images is about 2 MB; CSS and JS together are about 230 KB uncompressed (about 52 KB gzipped).
  • WebP images with explicit dimensions, loading="lazy" below the fold, and font preloading.
  • Enable gzip or Brotli compression and long-term caching on your host for the best scores.

Troubleshooting

Below are solutions for the most common setup questions and troubleshooting scenarios encountered when working with static HTML templates.

1. Changes to CSS or data aren't showing up in the browser

Modern browsers aggressively cache static assets. When you edit style.css or data.js:

  • Perform a hard reload: Ctrl + F5 (Windows/Linux) or Cmd + Shift + R (macOS).
  • Update the cache-busting version query string in the HTML <head>, e.g. assets/css/style.css?v=1.0.1.
  • Open DevTools (F12), switch to the Network tab, and check Disable cache while DevTools is open.

2. Cart or wishlist items do not persist after reloading

Some modern browsers (such as Safari and Chrome) restrict access to localStorage when pages are opened directly from the filesystem using the file:// protocol. Always preview the template through a local development server:

# Python 3
python3 -m http.server 8080

# or Node.js
npx serve .

Then navigate to http://localhost:8080 in your browser.

3. How to connect the contact form to a live email inbox

The included contact and newsletter forms feature client-side JavaScript validation. To send real emails without managing your own backend server, you can submit to a form forwarding service such as Formspree, UseBasin, or Netlify Forms:

<form action="https://formspree.io/f/your_form_id" method="POST">
  <!-- Existing form fields remain identical -->
</form>

4. How to integrate real payment processing

The checkout interface simulates an e-commerce order workflow without charging cards or storing customer credentials. To collect real payments, replace the simulated submit handler in assets/js/pages.js with a real gateway SDK (such as Stripe Checkout or PayPal JS SDK). Search for INTEGRATION POINT in pages.js and checkout.html for guided instructions.

5. My replacement images appear distorted or stretched

NEXORA uses modern CSS object-fit: cover to protect aspect ratios. For the cleanest visual presentation, match the native aspect ratios of the placeholder assets:

  • Product main & gallery images: 800 × 800 px (1:1 square)
  • Blog article covers: 1200 × 750 px (16:10 ratio)
  • Hero main image: 1312 × 816 px
  • About lineup photo: 1800 × 900 px (2:1 panoramic ratio)
